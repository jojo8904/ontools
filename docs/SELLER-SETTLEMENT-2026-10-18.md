# 무료 판매자 정산 비교

- 경로: `/seller-settlement` (레지스트리·canonical·사이트맵 등록).
- XLSX/UTF-8 CSV에서 시트와 키·금액 열을 고르는 범용 비교. 공식 마켓 내보내기 호환을 주장하지 않는다.
- 첫 실제 행은 제목, 키는 정확한 문자열 비교. XLSX 숫자 키는 선행 0/정밀도 손실 위험 때문에 제외한다. 금액은 십진 정수 센트, 소수 2자리, 반올림 없음. 차이는 정산−주문이다.
- 일치/금액 차이/한쪽 단독/중복/입력 오류와 원본 시트·행을 제공. CSV 행 번호는 따옴표 안 줄바꿈을 한 셀로 처리한 스프레드시트 레코드 번호다. 중복 키는 자동 합산하지 않는다. 미지급·회계 오류를 확정하지 않는다.
- 수식은 실행하지 않으며 캐시 값도 제외. 매크로/암호화/XLS 미지원. UTF-8 CSV, 5MB, 5시트, 시트당 데이터 10,000행/100열. ZIP 해제 항목 8MB/합계 24MB/500항목 제한.
- 기존 광고·분석은 다른 페이지에서 유지한다. 민감 입력은 별도의 route handler 문서와 `sandbox="allow-scripts allow-downloads"` iframe 안에만 존재한다. CSP sandbox도 같은 제한을 적용하며 `allow-same-origin`을 주지 않는다. 광고가 있는 부모와 DOM 접근/스토리지 공유를 차단한다. `connect-src 'none'`, form 차단, 외부 스크립트 차단. 부모에 postMessage/식별자/파일명을 보내지 않는다. 브라우저 확장/기기 보안은 별개다.
- 독립 React 번들은 `prebuild`/`predev`에서 생성한다. 기존 설치 트리에 이미 있던 esbuild 0.28.2를 직접 dev dependency로 명시했다. JSZip은 기존 런타임 의존성을 사용한다. 생성된 `public/settlement-workspace.js`는 Git/ESLint에서 제외한다. DB/비밀값/광고 공통 코드/정책 상수 변경 없음.
- React 파일 작업은 기존 `useLocalTask`/`useObjectUrls`를 사용한다. 다운로드에는 분석을 호출하는 공통 downloadBlob 대신 로컬 Blob 링크를 사용한다.

## 합성 예제와 블로그 인계

1. 도구의 `합성 예제로 시작` → `선택한 열 비교하기`.
2. 결과 7항목: 일치 2, 금액 차이 1, 중복 1, 주문 단독 1, 정산 단독 1, 입력 오류 1.
3. `00123`: 주문 10000.00, 정산 9700.00, 차이 -300.00. 긴 텍스트 주문번호와 음수 환불은 일치.
4. 예제 파일 다운로드는 작업 영역 아래 접힌 섹션에 있다. 실제 고객 자료는 필요 없다.
5. 소개 글용 실제 화면 추천: 예제 선택 후 양쪽 매핑/미리보기, 비교 후 상태 요약과 결과 표. E2E는 `seller-settlement-demo.png`를 각 기기 test-results에 저장한다. 아직 실행되지 않은 스크린샷을 실제 화면이라고 부르지 않는다.

## 검증

비교/CSV/XLSX 단위 테스트, 실제 production bundle의 DOM 통합 테스트, Playwright 데스크톱/모바일 파일 선택·비교·내보내기·부모 DOM/스토리지 격리·무전송 검사를 추가했다. 최종 결과는 배포 기록과 작업 인계에서 실제 실행 결과로 기록한다. 기존 클라우드 Chromium 정책 제약은 우회하지 않으며 브라우저 E2E는 GitHub CI로 확인한다.
