## 3. 반복 업무 매뉴얼

### 3-1. 배포 (코드·콘텐츠 변경 후)

```sh
cd C:\Users\83050\ontools
npm run lint
npm run typecheck
npx vitest run
npm run build
# 선택: npm run test:e2e
git add -A && git commit -m "..." && git push origin main
```

1. push 후 GitHub Actions `Quality Checks`(ci.yml)와 커밋 상태 `Vercel`이 성공하는지 확인.
2. 라이브 URL 몇 개를 열어 200 확인 (`/`, `/sitemap.xml`, 바뀐 페이지).
3. `docs/UPGRADE-PLAN-2026-09-24.md` 배포 기록 표에 한 줄 추가.
4. 새 페이지가 생겼으면 §3-4 색인 절차.

금지: force-push, 운영 DB 마이그레이션 재실행, 심사 중 애드센스 코드/ads.txt 변경.

### 3-2. 새 도구 추가

`CLAUDE.md` "새 도구 추가 절차" 그대로. 요약: `lib/tools.ts` 등록 → `app/(tools)/<slug>/page.tsx` (ToolShell + canonical) → 계산 로직 `features/<name>/utils.ts` + `utils.test.ts` → 정책 상수는 `lib/korea-policy.ts`에 출처와 함께. 안내·FAQ 본문은 1,500자 이상 목표(애드센스 저가치 판정 회피).

### 3-3. 도구 페이지 본문 보강 (안내 섹션 + FAQ)

1. `scripts/content/` 에 JSON 작성 (기존 batch 파일 형식 복사).
2. `node scripts/add-tool-content.mjs scripts/content/<file>.json` 실행. 중복 제목·질문은 자동으로 건너뜀.
3. 예시 숫자는 반드시 해당 계산기 코드로 검산. 도구 기능 설명은 컴포넌트와 대조.

### 3-4. 검색엔진 색인 (새 페이지 배포 후)

- **네이버·빙**: 자동. main push 시 `indexnow.yml`이 변경 URL 제출. 수동은 `npm run indexnow -- <url>` 또는 `--all`.
- **구글**: `.gsc-queue.txt`에 URL 한 줄씩 추가 → 로그온 시 작업 스케줄러가 하루 6건 자동 요청. 급하면 `npm run gsc:index -- <url>` (일 한도 약 10건).
- 사이트맵 lastmod: `lib/guides.ts` `GUIDE_DATES`, `app/sitemap.ts` `ROUTE_UPDATED`에 날짜 갱신.
- 구글 세션 풀림(로그에 "login needed") → `npm run gsc:index -- --login` 실행 후 창에서 운영자가 로그인.
- GSC 스크립트 두 개 동시 실행 금지(프로필 잠김). 남은 크롬 프로세스는 먼저 종료.

### 3-5. 정책 상수 갱신 (매년 말, 또는 요율 개정 시)

- 파일: `lib/korea-policy.ts`. 기간(상·하반기)별 구조. 출처 URL을 주석으로.
- 바뀌면 `features/salary/utils.test.ts` 등 기대값도 갱신, `/salary-table` 재생성, 관련 가이드(`lib/guides.ts`) 문구 갱신.
- 2027 작업 대기 중 (§6).

### 3-6. 자동 수집 모니터링 (주 1회)

- GitHub Actions 탭에서 `Exchange Rate Updater`(평일), `YouTube Video Crawler`(월요일) 최근 실행 초록 확인.
- 실패 시 Secrets 유효성(`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `YOUTUBE_API_KEY`) 확인 후 `Run workflow`로 수동 재실행.
- 사이트 환율 위젯에 "오래된 데이터"가 뜨면 수집 실패 신호.
- 60일 이상 커밋이 없으면 GitHub가 schedule을 끈다 → Actions 탭에서 Enable, 또는 `docs/SETUP-CRON.md`대로 cron-job.org 설정.

### 3-7. 의존성 업그레이드

## 8. 모두가 지켜야 할 규칙

1. service_role 키, API 키, 토큰은 코드·문서·대화에 넣지 않는다. `NEXT_PUBLIC_*`만 브라우저 노출 허용.
2. 파일 처리 도구는 서버로 파일을 보내지 않는다(브라우저 로컬 처리). 분석 이벤트에 파일명·급여·비밀번호·이미지 내용 금지.
3. 정책 숫자(세율·요율·요금)는 출처 없이 바꾸지 않는다. 바꾸면 테스트와 가이드도 같이.
4. 운영 DB 마이그레이션은 005까지 적용 완료. 재실행 금지. 새 마이그레이션은 `supabase/tests/security.test.ts` 통과 필수.
5. 애드센스 심사 중에는 광고 코드와 ads.txt를 건드리지 않는다.
6. `main` 직접 push가 배포다. lint·typecheck·vitest·build 통과 전 push 금지. force-push 금지.
7. 큰 의존성 업그레이드(Zod 4, React 19, Tailwind 4, ESLint 10, TS 7)는 문서의 순서 없이 올리지 않는다.
8. GSC 자동화 스크립트는 한 번에 하나만, 하루 10건 이내.
