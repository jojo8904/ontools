# 온툴즈 코드 진단 - 2026-09-18

현재 워크스페이스 기준 진단이다. 애플리케이션 코드는 변경하지 않았다. 아래 위치의 줄 번호는 진단 시점 기준이다.

## 우선 처리할 문제

### 1. [P1] DB 쓰기 정책이 service_role로 제한되지 않음

- 위치: `supabase/migrations/001_create_tables.sql:38`, `:41`, `supabase/migrations/003_create_youtube_videos.sql:20`, `:21`.
- 정책 이름은 `Allow service_role ...`이지만 실제 SQL에는 `TO service_role`이 없다. INSERT는 `WITH CHECK (true)`, DELETE는 `USING (true)`다.
- 역할을 생략한 정책은 PUBLIC에 적용된다. 배포 DB에 이 정책과 anon/authenticated의 해당 테이블 권한이 함께 존재하면, 공개 클라이언트 키로 환율/뉴스/영상 삽입 및 영상 삭제가 가능하다.
- 실제 운영 DB의 정책과 GRANT는 확인하지 않았다. 따라서 현재 운영 DB가 노출됐다고 단정할 수는 없지만, 저장소의 마이그레이션은 의도한 제한을 구현하지 않는다.
- 개선: 새 마이그레이션으로 클라이언트 역할의 쓰기 권한과 공개 쓰기 정책을 제거하고 SELECT만 허용한다. service_role은 서버 작업에서만 사용한다. 기존 마이그레이션 수정만으로 이미 배포된 DB가 고쳐지지는 않는다.
- 검증: 격리된 DB에서 anon/authenticated의 INSERT/DELETE 거부와 service_role 쓰기 성공을 테스트한다.

근거: [PostgreSQL CREATE POLICY](https://www.postgresql.org/docs/current/sql-createpolicy.html), [Supabase RLS와 GRANT](https://supabase.com/docs/guides/database/postgres/row-level-security).

### 2. [P1] PDF 변환 기능이 알려진 취약 버전과 기본 옵션을 사용함

- 위치: `app/(tools)/pdf-to-image/PdfToImage.tsx:35`, `:38`, `package.json`.
- 설치 버전은 `pdfjs-dist@3.11.174`. `getDocument({ data: buf })`에 `isEvalSupported: false`가 없다.
- 이 조합은 CVE-2024-4367의 영향 조건에 해당한다. 사용자가 악성 PDF를 열면 사이트의 브라우저 실행 문맥에서 임의 JavaScript가 실행될 수 있다.
- 개선: 해당 옵션을 비활성화하는 임시 완화와 함께 수정된 지원 버전으로 업데이트한다. 패키지와 worker의 버전/배포 방식을 같이 검증해야 한다. 해당 CVE 최초 수정 버전이 현재의 권장 최신 버전이라는 뜻은 아니다.
- 실제 악성 PDF를 실행하지 않았으며, 설치 버전/호출 옵션을 공급자 공지와 대조했다.

근거: [Mozilla PDF.js 보안 공지](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq).

### 6. [P2] 원화에서 외화로 바꿀 때 적용 환율의 방향이 반대

### 7. [P2] 마스킹 편집 후에도 이전 결과를 다운로드할 수 있음

### 8. [P2] 비밀번호 일부를 비암호학적 난수로 생성

- 위치: `app/(tools)/password-generator/PasswordGenerator.tsx:25`, `:30`, `:44`.
- 일반 문자는 `crypto.getRandomValues()`를 사용하지만 필수 문자 선택과 셔플은 `Math.random()`에 의존한다.
- 길이 4, 모든 옵션 활성화에서는 네 문자가 전부 필수 문자로 채워져 crypto 난수가 결과에 전혀 쓰이지 않는다.
- 실제 콜백을 추출해 crypto는 그대로 두고 `Math.random`만 고정했을 때 생성 결과가 반복되는 것을 확인했다. 이는 일반 사용 환경에서 항상 같은 비밀번호가 나온다는 뜻이 아니라, 이 경로가 crypto 난수에 의존하지 않는다는 검증이다.
- 개선: 문자 선택과 Fisher-Yates 셔플 모두 crypto 기반으로 구현하고, 인덱스 생성은 rejection sampling으로 편향을 제거한다.

### 9. [P2] 유튜브 수집 전체 실패가 성공으로 종료됨

- 개선: 전체 또는 허용 범위를 넘는 실패는 종료 코드 1로 처리하고 알림을 연결한다. 환율 수집기는 이미 오류 합계로 실패를 반환하고 있어 그 패턴을 재사용할 수 있다.

### 11. [P2] PDF 페이지 범위 입력으로 화면이 멈출 수 있음

- 위치: `app/(tools)/pdf-merge/PdfMerge.tsx:27`.
- 범위의 각 숫자를 순회하면서 PDF 페이지 안에 있는지 검사한다. 예를 들어 10페이지 PDF에 `1-1000000000000`을 넣어도 1조 번 순회를 시도한다.
- 실제 파서를 격리 실행했을 때 정상 입력 `1-3,5`는 `[0,1,2,4]`로 끝났고 큰 범위는 200ms 실행 제한으로 중단됐다. 브라우저 UI에는 이 제한이 없다.
- 개선: 순회 전에 시작/종료를 실제 페이지 범위로 제한하고 유한한 안전 정수만 받는다. 유효 범위가 없으면 오류를 반환한다.

### 12. [P2] 이미지·PDF 결과의 Blob URL이 정리되지 않음

- 대표 위치: `app/(tools)/pdf-to-image/PdfToImage.tsx:55`, `:86`, `:90`, `app/(tools)/image-compress/ImageCompress.tsx:136`, `app/(tools)/bg-remove/BgRemove.tsx:54`.
- 결과 교체, 초기화, 컴포넌트 해제 시 URL을 revoke하지 않는 경로가 여러 개 있다. 원본 로딩용 임시 URL을 정리하는 것과 결과 URL 수명 관리는 별개다.
- PDF는 모든 페이지 결과와 ZIP 생성 데이터를 메모리에 보유한다. 긴 문서를 반복 처리하면 모바일에서 메모리 부담이 커진다.
- 개선: 결과 URL의 소유권/해제 시점을 정하고 교체·초기화·해제 시 정리한다. 다운로드용 URL은 사용 완료 후 해제한다. PDF는 페이지/픽셀/용량 제한과 취소를 제공한다.
- 누락은 코드로 확인했으며 실제 기기별 메모리 사용량은 측정하지 않았다.

### 13. [P2] 개발 검증이 불완전하고 지원 종료 의존성이 남아 있음

- `npm run lint`는 검사 대신 ESLint 최초 설정 질문을 출력하고 종료 코드 1로 끝났다. 저장소에 ESLint 설정이 없다.
- 테스트는 BMI·환율·연봉의 3파일, 29개뿐이다. PDF/이미지 처리 상태, DB 권한, 크롤러 실패, 연도별 정책 변경은 포함되지 않는다.
- GitHub Actions에는 환율/유튜브 스케줄러만 있고 PR 빌드·테스트 검증 워크플로우는 없다.
- 설치된 Next.js는 14.2.35이며 공식 지원 정책에서 14.x는 지원 종료 상태다.
- `npm audit --omit=dev`는 영향받는 패키지 14개를 보고했다: critical 2, high 9, moderate 1, low 2. 간접·선택 의존성도 포함된 수치이며 전부 운영에서 공격 가능하다는 뜻은 아니다. PDF.js처럼 실제 사용 경로가 확인되는 항목부터 처리한다.
- 개선: lint 설정과 PR 검증을 추가하고, 지원 중인 Next.js 버전 및 의존성으로 단계적으로 업데이트한다. `audit fix --force` 일괄 적용 대신 호환성 변경과 worker/빌드 설정을 검토한다.

근거: [Next.js 지원 정책](https://nextjs.org/support-policy).

### 14. [P2] AdSense 수동 광고 단위는 현재 비활성 상태

- 위치: `components/AdUnit.tsx:7`, `:33`, `components/RelatedTools.tsx:28`, `app/page.tsx:348` 및 여러 계산기 페이지.
- 저장소의 AdUnit 호출은 슬롯 `0000000000`을 사용한다. 컴포넌트는 이 값을 만나면 `null`을 반환하므로 클라이언트 ID만 설정해도 해당 수동 광고는 나오지 않는다.
- 개선: 발급된 슬롯 ID를 환경/위치별 설정으로 연결하고 실제 배포에서 요청·노출을 검증한다.
- AdFit은 별도 코드가 있다. AdSense 자동 광고 설정, 승인 상태, 실제 노출과 수익은 확인하지 않았으므로 사이트 전체가 무수익이라고 결론 내릴 수 없다.

## 추가 점검 항목

- `app/(tools)/bg-remove/BgRemove.tsx:111`: 처리 중에도 다른 사진으로 초기화할 수 있는데 이전 작업을 취소하거나 결과를 무시하지 않는다. 느린 처리 중 파일을 바꾸면 이전 결과가 새 상태에 들어올 수 있어 작업 ID 관리가 필요하다. 실제 모델 다운로드를 포함한 브라우저 재현은 하지 않았다.

- `app/layout.tsx:10`: 현재 기능 구성과 달리 대표 메타데이터는 AI 뉴스 포털을 설명한다. 실제 제공하는 도구·가이드에 맞추는 것이 좋다.
- 정적 HTML 93개에 명시적인 canonical 링크가 없다. URL 정규화 정책과 함께 페이지별 canonical을 정한다. 이것만으로 검색 노출 실패라고 단정할 수는 없다.
- `app/sitemap.ts:44`: 모든 페이지의 lastModified가 생성 시각이다. 실제 콘텐츠 수정일을 사용하거나 신뢰 가능한 날짜가 없으면 생략한다.
- `features/electricity/utils.ts:3`: 코드가 2024년 기준임을 명시한다. 전기요금, 세금, 건강 정보 도구 전체에 출처·적용일·마지막 검토일을 붙이고 별도 기준 검증을 진행할 필요가 있다. 이번 진단이 모든 제도 계산식의 완전한 검증은 아니다.
